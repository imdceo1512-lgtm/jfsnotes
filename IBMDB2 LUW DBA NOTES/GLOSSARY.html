Glossary

TermMeaning in this course
ActivationBringing a database online in an instance so it can serve connections.
AgentDb2 worker that services a request; not identical to an application connection.
AliasLocal database directory name used by a client to refer to a database.
Archive logA completed transaction log retained for recovery or standby use.
AuthorityDatabase- or instance-level administrative capability, such as DBADM or SYSADM.
BufferpoolMemory area that caches table and index pages.
CatalogDb2 system metadata describing databases, objects, privileges, and dependencies.
CF (cluster caching facility)pureScale component coordinating shared cache and locking across members.
CLPDb2 command line processor; it parses commands, options, and statement terminators.
ContainerStorage allocation assigned to a table space; its form depends on storage management.
Data partitionOne unit of data placement in a partitioned database (DPF).
DBADMDatabase administration authority. In Db2 12.1 it no longer implies DATAACCESS or ACCESSCTRL by default.
DB2INSTANCEEnvironment variable selecting the Db2 instance profile/context.
DPFDatabase partitioning feature; data and workload are distributed across database partitions.
EDUEngine dispatchable unit, a Db2 process or thread performing work.
Event monitorFacility that records selected database activities to a chosen target.
FODCFirst occurrence data capture; diagnostic data collected to investigate a problem.
HADRHigh availability disaster recovery; log-based primary/standby replication for Db2 databases.
High water markHighest used storage point; lowering it may require a separate reclamation operation.
Incremental backupBackup containing changes since the most recent successful full backup.
Delta backupBackup containing changes since the most recent successful full, incremental, or delta backup.
InstanceDb2 engine environment that owns configuration and can manage multiple databases.
LBACLabel based access control; access is governed by security labels.
LSN/log positionPosition in a transaction log stream used to describe send, receive, replay, or recovery progress.
NicknameLocal federated object describing a remote table or view.
PackageBound form of application SQL statements and access plans.
Peer stateHADR state in which primary and standby are synchronized under the configured mode.
Point-in-time recoveryRecovery that stops at a chosen timestamp/log point rather than the latest available log.
pureScaleDb2 clustered architecture with members, cluster caching facilities, and shared storage.
RebindRecreate a package so Db2 can resolve dependencies and generate sections/plans.
Reclaim extentsReturn eligible unused extents to the table space; it does not recluster data.
Redirected restoreRestore operation that changes storage path/container mapping before completion.
ReintegrateBring a former HADR primary back as standby when Db2 can safely synchronize it.
RollforwardApply transaction logs after restore to reach a consistent recovery point.
RPORecovery point objective: acceptable data loss measured in time or transactions.
RTORecovery time objective: acceptable service recovery time including validation and routing.
RUNSTATSUtility that collects table/index statistics used by the optimizer.
SQLCODE / SQLSTATENumeric and standardized status values returned for SQL/Db2 outcomes.
TablespaceLogical storage layer containing table and index objects.
TLSTransport layer security for protecting client/server network communication.
Unit of workA transaction's work between commit/rollback boundaries.
User mappingFederated mapping from a local authorization identity to remote credentials/options.
WrapperFederated component that communicates with a class of remote data sources.
WLMDb2 workload management facilities for grouping, prioritizing, and controlling work.

Use the IBM reference linked in each lesson for release-specific definitions and behavior.
