Lab index

All labs are designed for disposable systems. No lab is marked executed because no Db2 installation was available.

  • A-01 Host, server, virtualization, capacity, and failure domains — Build a host inventory for a fictional four-vCPU Db2 VM. Add CPU model, NUMA nodes, guest memory limit, storage latency, and host failure domain. Create two timelines, one CPU-bound and one steal-bound. Explain which owner receives each incident. Cleanup: keep the report as lab evidence; make no VM changes.
  • A-02 Linux identity, filesystems, permissions, limits, and services — Compare account resolution and path permissions on two lab hosts. Write a service-start checklist that identifies which steps belong to root, the instance owner, and systemd. Do not change production ownership. Cleanup: remove only the disposable test directory.
  • A-03 CPU, memory, process, paging, and Db2 EDU diagnosis — Collect a five-interval vmstat sample and two Db2 EDU samples against a disposable database. Label each signal as demand, wait, or capacity. For a safe failure drill, use a CPU-only bounded test process in a container with a low CPU quota; compare guest CPU with throttling counters. Stop the test process and verify normal scheduler values.
  • A-04 Storage, filesystems, multipath, capacity, and I/O diagnosis — On a disposable filesystem, create a small file and keep it open while unlinking it; observe that df and du differ, then close the handle and verify free space returns. Do not use Db2 log paths for this drill.
  • A-05 Networking, DNS, ports, firewalls, time, and client/server evidence — Use a disposable client/server pair. Break one layer at a time: wrong DNS name, closed test port, then untrusted test CA. Record the client result, server evidence, and the smallest fix. Restore original config and prove the successful authenticated connection.
  • H-01 Baselines, workload measurement, service objectives, and bottleneck isolation — Create a fixed synthetic query mix at two concurrency levels. Record throughput, p95 and Db2/OS counters before and after a controlled index or memory experiment. Roll back if any service class breaches its objective.
  • H-02 Compilation, access plans, EXPLAIN tables, db2exfmt, and plan interpretation — Explain a selective lookup and a broad scan on synthetic APP.ORDERS. Compare estimated rows, joins and index use; alter statistics in a disposable schema and observe plan changes. Cleanup explain rows after saving relevant plan text.
  • H-03 Statistics, cardinality, skew, parameter markers, optimizer choices, and rebind — Create skewed synthetic statuses, run baseline explain with representative values, collect distribution stats, and compare estimates. Rebind one lab package with REOPT NONE/ONCE, measure compilation and execution. Cleanup package/test data.
  • H-04 Index and query design, read/write costs, and measured plan changes — Build APP.ORDERS with existing primary key, compare date-only and region/date query plans, create one candidate index and replay mixed reads/inserts. Remove only lab index/table after results recorded.
  • H-05 Locks, deadlocks, isolation, transaction design, and safe intervention — Open two disposable sessions, acquire row locks in opposing order, create a deadlock, capture event output and identify victim. Separate run: create a lock wait and time out. Verify rollback and no lingering locks; cleanup test rows.
  • H-06 Bufferpools, sort, package cache, memory pressure, and competing consumers — Run a sort-heavy lab query at two concurrency levels. Capture sort spill, memory sets, host paging and temporary space. Change only SORTHEAP; compare all metrics and rollback.
  • H-07 Workload management, I/O, utility contention, and maintenance tuning — Create one service class and a workload for synthetic reporting identity. Verify classification; run a low-volume maintenance utility and inspect device/Db2 metrics. Do not tune thresholds under actual service load.
  • G-01 HA versus DR versus backup, failure domains, and service restoration objectives — Create a failure matrix for host, disk, site, logical delete and key-manager outage. Map each to HADR, backup, service routing and data validation. Tabletop a DR takeover and time every stage.
  • G-02 HADR roles, states, synchronization modes, queues, and guarantees — Build a state table from fictional HADR samples covering LOCAL_CATCHUP, REMOTE_CATCHUP, PEER, DISCONNECTED_PEER and DISCONNECTED. For each mode, list what a commit acknowledgement means and what can be lost. No HADR pair is available here.
  • G-03 HADR setup, planned takeover, forced takeover gates, reintegration, and failback — Tabletop planned takeover with zero loss and forced takeover after three different sync modes. In the forced case, identify fencing evidence, possible gap and owner acceptance. Follow old-primary reintegration/reinitialize branches. Do not execute failover without a disposable pair.
  • G-04 HADR delay, log transport/replay diagnosis, and safe remediation — Analyze three 10-second HADR snapshots: send backlog, receive backlog and replay backlog. For each locate stage, owner, safest action and recheck. Include one SQL1770N scenario: state does not meet takeover eligibility. No HADR lab exists.
  • G-05 Q Replication and SQL Replication operations; keep CDC as a distinct product track — Draw three independent sequence diagrams for Q, SQL Replication and CDC. Use official docs to write a start/stop/resync checklist and compare where backlog resides: MQ, CD table, or CDC engine. No replication product is installed here.
  • G-06 Separate DPF and pureScale architecture, command scope, failures, and labs — Build independent DPF and pureScale runbooks. DPF lab: inspect node map and rebalance status. pureScale tabletop: member host loss, CF loss and site loss. Mark cluster manager owner and exact recovery evidence; no clusters are available here.
  • F-01 Circular/archive logging, log paths, sizing, log chains, and log-full diagnosis — In a disposable recoverable database, set a small log configuration, generate a bounded transaction, observe UOW/log usage, and commit/rollback. Demonstrate archive path capacity fault only using a controlled test directory. Re-establish log archive and test archive retrieval.
  • F-02 RPO/RTO, backup design, retention, capacity, encryption, and restore rehearsal — Design backup policy for a 2 TB OLTP database with 15-minute RPO and 2-hour RTO. Estimate image, logs, staging and offsite capacity from stated rates. Run a timed lab restore and compare with objective. Cleanup: keep test evidence, delete only disposable images under retention.
  • F-03 Backup types and command selection: offline, online, full, incremental, delta, database, tablespace, LOAD copy, snapshot, and vendor media — For each branch create a written command choice and recovery sequence: offline, online full, incremental, delta, database, tablespace, LOAD copy, snapshot and vendor media. In a lab, run offline/online/incremental only if authorized Db2 environment exists. This package environment has none, so all are not executed.
  • F-04 Backup execution, progress, history, image verification, and failure handling — Run a backup to a disposable directory, monitor LIST UTILITIES, inspect history and db2ckbkp -h, then restore a copy to an isolated alias if lab exists. Deliberate safe drill: rename one copy of a multi-piece lab image and verify validation failure; restore filename and recheck.
  • F-05 Full and redirected restore, alternate targets, path changes, and post-restore validation — Restore an offline test image to QA1, then generate and review a redirected script for a second disposable target. Check every path and storage group before running. For online image test, supply archived logs and STOP at an agreed endpoint. Cleanup only test aliases.
  • F-06 Automatic/manual incremental and delta restore chains — Build a chain worksheet from fictional full/incremental/delta timestamps. Resolve a missing middle image and identify whether any legal restore reaches target. In a disposable Db2 lab, test automatic restore and db2ckrst; none was available in current environment. Cleanup QA2 and media only after validation.
  • F-07 Rollforward, end-of-logs, point-in-time recovery, STOP/COMPLETE decisions, and missing logs — Use a disposable restore and create timestamped transactions around an announced bad commit. Recover once to end-of-logs and once to an earlier PIT; compare rows and explain data loss. Practice query status before STOP. Cleanup recovered lab aliases.
  • F-08 Tablespace backup and recovery, online/offline behavior, and consistency checks — Place parent and child tables in separate lab tablespaces. Back up them and perform an isolated table-space restore/rollforward in a clone. Check dependencies and data time point. No lab server is available here, so command path is not executed. Cleanup the clone only after preserving evidence.
  • F-09 Recovery failure drills, decision trees, legal next steps, evidence, and measured RTO — Run tabletop drills for corrupt stripe, missing log, expired key, full restore volume and wrong database alias. For each, list evidence, legal next action, terminal point, business decision and elapsed time. Do not stage destructive failure in an unavailable/non-disposable system.
  • D-01 Authentication, operating-system identity, providers, and security plugins — Configure two synthetic identities in a disposable directory/lab model. Trace provider lookup, connection authentication, CURRENT USER/SESSION_USER and group authorization. Failure drill: disable only the test provider route, observe sanitized failure evidence, restore and retest.
  • D-02 Authorities, privileges, roles, groups, ownership, and effective access — Create a reader role, grant SELECT on one synthetic table, assign one test group/user, and verify allowed/denied operations. Then model Db2 12.1 DBADM without DATAACCESS/ACCESSCTRL. Cleanup: revoke only lab grants and drop role after removing memberships.
  • D-03 Client catalogs, aliases, drivers, connection configuration, and reroute — Create an isolated alias to SAMPLE, test with db2cli validate, then change its host to a closed test port and capture the error layer. Restore correct host, connect and confirm CURRENT SERVER. Cleanup: uncatalog only the test alias/node.
  • D-04 TLS, certificates, keystores, native database encryption, and backup encryption — In a disposable pair, create a local test certificate, configure a second TLS port, connect with trusted and untrusted clients, and restore an encrypted backup using a separately custodied test key. Cleanup certificates/images with secure deletion procedure; never reuse key material.
  • D-05 Auditing, RCAC, masks, LBAC, and sensitive-data controls — Create a three-row customer table with two regions and a masked test column. Build row permission and mask in a disposable database; test as two app users and SECADM. Add an audit policy, execute one SELECT and extract a record. Separately draw LBAC component/policy/label steps. Cleanup only lab objects and audit logs.
  • D-06 Layer-by-layer security and connectivity failure diagnosis — Walk four intentionally distinct cases on a test pair: wrong alias, blocked test port, untrusted CA and valid connection with missing SELECT. For each record symptom, proof, owner and layer-specific fix. Cleanup: restore aliases/firewall test rule/certificate and remove test grants.
  • E-01 Incident scope, timeline, baseline, and evidence quality — Create a timeline for a fictional connectivity outage with client, firewall, listener and db2diag times across three timezones. Normalize to UTC and mark uncertainty. Cleanup: redact invented user identifiers in the report.
  • E-02 db2diag.log, notification logs, diagnostic signatures, and FODC — Use a sample diagnostic log from IBM documentation or a disposable instance. Filter a known timestamp/signature, map EDUID/member, and create an evidence checklist. Simulate low disk by quota planning only; do not fill production logs.
  • E-03 db2pd, monitor table functions, and snapshots — Collect a one-time db2pd sample and a MON_GET_CONNECTION sample against disposable SAMPLE. Add second samples five seconds apart, classify counters/gauges, and document member scope. Cleanup: disconnect test session.
  • E-04 Connections, applications, agents, transactions, and long-running work — Create two lab sessions: one holds a row lock and one waits. Observe handles/UOWs, cancel the waiter, then use a second disposable run to terminate only the blocker and watch rollback. Verify no open test locks remain.
  • E-05 Event-monitor families, targets, lifecycle, storage, and interpretation — Create a lock event monitor in a lab, activate capture, induce a short lock wait and one deadlock between test sessions, then query formatted events. Deactivate and archive outputs. Cleanup monitor plus only its lab tables/files.
  • E-06 Db2/OS observability, metric definitions, alerts, and operational reporting — Define an alert for log capacity and one for query latency. For each write unit, scope, sampling interval, sustained threshold, reset/no-data condition, owner and response. Feed synthetic reset and missing data into a spreadsheet/test harness; do not change production alert routes.
  • C-01 SQL, transactions, isolation, SQLCODE, and SQLSTATE fundamentals — Create a lab inventory row and run a guarded decrement with autocommit off. Induce an insufficient-stock zero-row update; test COMMIT and ROLLBACK separately. Cleanup: restore or delete only the synthetic row.
  • C-02 Schemas, tables, data types, indexes, constraints, and dependencies — Build APP.ORDER_LINE with a primary key, check constraint and secondary index. Attempt one invalid row, read the exact SQLSTATE, then explain a filter on sku. Cleanup in dependency order: remove dependents, index and table.
  • C-03 Db2 catalogs, administrative views, monitor functions, and snapshots — Run an object catalog query and a MON_GET_TABLESPACE query at two timestamps. Label which fields are definitions, gauges, or cumulative counters; explain why a zero-row monitor result can be valid.
  • C-04 Tablespaces, storage groups, containers, AUTORESIZE, and space reclamation — Create an automatic-storage tablespace in a disposable database with a small bounded maximum. Observe initial allocation and monitor view. Use documentation to compare LOWER HIGH WATER MARK and REDUCE; do not fill disks intentionally. Cleanup: drop lab tablespace only after checking it contains no other objects.
  • C-05 EXPORT, IMPORT, LOAD, INGEST, db2move, and db2look — Prepare a small synthetic input with one valid row, one duplicate key and one malformed numeric field. Run each utility separately against disposable staging tables. Compare triggers/constraints, messages and restart behavior. Cleanup each staging table and remove only the generated lab files.
  • C-06 RUNSTATS, REORGCHK, table REORG, index REORG, types, phases, and monitoring — In a disposable database, create a table with clustered and non-clustered indexes, update/delete rows, and capture RUNSTATS/REORGCHK. Compare the six distinct operations above by goal and eligible organization. Safe drill: pause/resume an inplace operation while restating options; verify preserved .OLR; never use rm. Cleanup via documented stop/complete flow, then drop lab objects.
  • C-07 Integrity, pending states, exception tables, dependencies, and package maintenance — In a lab schema, create rows including one constraint violation, add a constraint in a way that creates pending work, capture the reason state, then move/fix invalid rows and validate. Verify package validity after a harmless DDL change. Cleanup in dependency order.
  • B-01 Instances, databases, members, agents, and Db2 request path — Trace a synthetic SELECT from driver to listener to application handle to table-space read. Mark where database configuration, package cache, bufferpool and log appear. Cleanup: detach/reset only your lab connection.
  • B-02 Installation copies, licensing, instance creation, profiles, and service lifecycle — Install only in an isolated disposable VM. Compare response-file and package-install paths, create an instance, validate owner and service restart after a planned reboot.   • B-03 Database creation, activation, connections, and configuration scope — Create SAMPLE and save all three configuration views.   • B-04 CLP, SQL boundaries, command files, terminators, quoting, and safe workflows — Create a script with a compound SQL body, one deliberate syntax error in a disposable file, and a following marker statement.   • B-05 Agents, EDUs, units of work, and Db2 memory areas — Use a small synthetic workload with one long transaction and one sort-heavy query. Observe UOW age, EDU states and memory sets in separate snapshots. Commit/rollback only your test work; verify normal memory and connection counts afterward.
