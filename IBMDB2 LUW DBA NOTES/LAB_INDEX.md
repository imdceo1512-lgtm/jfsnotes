# Lab index

All labs are designed for disposable systems. No lab is marked executed because no Db2 installation was available.

- [A-01 Host, server, virtualization, capacity, and failure domains](./A/A-01.md#8-practice) — Build a host inventory for a fictional four-vCPU Db2 VM. Add CPU model, NUMA nodes, guest memory limit, storage latency, and host failure domain. Create two timelines, one CPU-bound and one steal-bound. Explain which owner receives each incident. Cleanup: keep the report as lab evidence; make no VM changes.
- [A-02 Linux identity, filesystems, permissions, limits, and services](./A/A-02.md#8-practice) — Compare account resolution and path permissions on two lab hosts. Write a service-start checklist that identifies which steps belong to root, the instance owner, and systemd. Do not change production ownership. Cleanup: remove only the disposable test directory.
- [A-03 CPU, memory, process, paging, and Db2 EDU diagnosis](./A/A-03.md#8-practice) — Collect a five-interval vmstat sample and two Db2 EDU samples against a disposable database. Label each signal as demand, wait, or capacity. For a safe failure drill, use a CPU-only bounded test process in a container with a low CPU quota; compare guest CPU with throttling counters. Stop the test process and verify normal scheduler values.
- [A-04 Storage, filesystems, multipath, capacity, and I/O diagnosis](./A/A-04.md#8-practice) — On a disposable filesystem, create a small file and keep it open while unlinking it; observe that `df` and `du` differ, then close the handle and verify free space returns. Do not use Db2 log paths for this drill.
- [A-05 Networking, DNS, ports, firewalls, time, and client/server evidence](./A/A-05.md#8-practice) — Use a disposable client/server pair. Break one layer at a time: wrong DNS name, closed test port, then untrusted test CA. Record the client result, server evidence, and the smallest fix. Restore original config and prove the successful authenticated connection.
- [H-01 Baselines, workload measurement, service objectives, and bottleneck isolation](./H/H-01.md#8-practice) — Create a fixed synthetic query mix at two concurrency levels. Record throughput, p95 and Db2/OS counters before and after a controlled index or memory experiment. Roll back if any service class breaches its objective.
- [H-02 Compilation, access plans, EXPLAIN tables, db2exfmt, and plan interpretation](./H/H-02.md#8-practice) — Explain a selective lookup and a broad scan on synthetic APP.ORDERS. Compare estimated rows, joins and index use; alter statistics in a disposable schema and observe plan changes. Cleanup explain rows after saving relevant plan text.
- [H-03 Statistics, cardinality, skew, parameter markers, optimizer choices, and rebind](./H/H-03.md#8-practice) — Create skewed synthetic statuses, run baseline explain with representative values, collect distribution stats, and compare estimates. Rebind one lab package with REOPT NONE/ONCE, measure compilation and execution. Cleanup package/test data.
- [H-04 Index and query design, read/write costs, and measured plan changes](./H/H-04.md#8-practice) — Build APP.ORDERS with existing primary key, compare date-only and region/date query plans, create one candidate index and replay mixed reads/inserts. Remove only lab index/table after results recorded.
- [H-05 Locks, deadlocks, isolation, transaction design, and safe intervention](./H/H-05.md#8-practice) — Open two disposable sessions, acquire row locks in opposing order, create a deadlock, capture event output and identify victim. Separate run: create a lock wait and time out. Verify rollback and no lingering locks; cleanup test rows.
- [H-06 Bufferpools, sort, package cache, memory pressure, and competing consumers](./H/H-06.md#8-practice) — Run a sort-heavy lab query at two concurrency levels. Capture sort spill, memory sets, host paging and temporary space. Change only SORTHEAP; compare all metrics and rollback.
- [H-07 Workload management, I/O, utility contention, and maintenance tuning](./H/H-07.md#8-practice) — Create one service class and a workload for synthetic reporting identity. Verify classification; run a low-volume maintenance utility and inspect device/Db2 metrics. Do not tune thresholds under actual service load.
- [G-01 HA versus DR versus backup, failure domains, and service restoration objectives](./G/G-01.md#8-practice) — Create a failure matrix for host, disk, site, logical delete and key-manager outage. Map each to HADR, backup, service routing and data validation. Tabletop a DR takeover and time every stage.
- [G-02 HADR roles, states, synchronization modes, queues, and guarantees](./G/G-02.md#8-practice) — Build a state table from fictional HADR samples covering LOCAL_CATCHUP, REMOTE_CATCHUP, PEER, DISCONNECTED_PEER and DISCONNECTED. For each mode, list what a commit acknowledgement means and what can be lost. No HADR pair is available here.
- [G-03 HADR setup, planned takeover, forced takeover gates, reintegration, and failback](./G/G-03.md#8-practice) — Tabletop planned takeover with zero loss and forced takeover after three different sync modes. In the forced case, identify fencing evidence, possible gap and owner acceptance. Follow old-primary reintegration/reinitialize branches. Do not execute failover without a disposable pair.
- [G-04 HADR delay, log transport/replay diagnosis, and safe remediation](./G/G-04.md#8-practice) — Analyze three 10-second HADR snapshots: send backlog, receive backlog and replay backlog. For each locate stage, owner, safest action and recheck. Include one SQL1770N scenario: state does not meet takeover eligibility. No HADR lab exists.
- [G-05 Q Replication and SQL Replication operations; keep CDC as a distinct product track](./G/G-05.md#8-practice) — Draw three independent sequence diagrams for Q, SQL Replication and CDC. Use official docs to write a start/stop/resync checklist and compare where backlog resides: MQ, CD table, or CDC engine. No replication product is installed here.
- [G-06 Separate DPF and pureScale architecture, command scope, failures, and labs](./G/G-06.md#8-practice) — Build independent DPF and pureScale runbooks. DPF lab: inspect node map and rebalance status. pureScale tabletop: member host loss, CF loss and site loss. Mark cluster manager owner and exact recovery evidence; no clusters are available here.
- [F-01 Circular/archive logging, log paths, sizing, log chains, and log-full diagnosis](./F/F-01.md#8-practice) — In a disposable recoverable database, set a small log configuration, generate a bounded transaction, observe UOW/log usage, and commit/rollback. Demonstrate archive path capacity fault only using a controlled test directory. Re-establish log archive and test archive retrieval.
- [F-02 RPO/RTO, backup design, retention, capacity, encryption, and restore rehearsal](./F/F-02.md#8-practice) — Design backup policy for a 2 TB OLTP database with 15-minute RPO and 2-hour RTO. Estimate image, logs, staging and offsite capacity from stated rates. Run a timed lab restore and compare with objective. Cleanup: keep test evidence, delete only disposable images under retention.
- [F-03 Backup types and command selection: offline, online, full, incremental, delta, database, tablespace, LOAD copy, snapshot, and vendor media](./F/F-03.md#8-practice) — For each branch create a written command choice and recovery sequence: offline, online full, incremental, delta, database, tablespace, LOAD copy, snapshot and vendor media. In a lab, run offline/online/incremental only if authorized Db2 environment exists. This package environment has none, so all are not executed.
- [F-04 Backup execution, progress, history, image verification, and failure handling](./F/F-04.md#8-practice) — Run a backup to a disposable directory, monitor LIST UTILITIES, inspect history and `db2ckbkp -h`, then restore a copy to an isolated alias if lab exists. Deliberate safe drill: rename one copy of a multi-piece lab image and verify validation failure; restore filename and recheck.
- [F-05 Full and redirected restore, alternate targets, path changes, and post-restore validation](./F/F-05.md#8-practice) — Restore an offline test image to QA1, then generate and review a redirected script for a second disposable target. Check every path and storage group before running. For online image test, supply archived logs and STOP at an agreed endpoint. Cleanup only test aliases.
- [F-06 Automatic/manual incremental and delta restore chains](./F/F-06.md#8-practice) — Build a chain worksheet from fictional full/incremental/delta timestamps. Resolve a missing middle image and identify whether any legal restore reaches target. In a disposable Db2 lab, test automatic restore and db2ckrst; none was available in current environment. Cleanup QA2 and media only after validation.
- [F-07 Rollforward, end-of-logs, point-in-time recovery, STOP/COMPLETE decisions, and missing logs](./F/F-07.md#8-practice) — Use a disposable restore and create timestamped transactions around an announced bad commit. Recover once to end-of-logs and once to an earlier PIT; compare rows and explain data loss. Practice query status before STOP. Cleanup recovered lab aliases.
- [F-08 Tablespace backup and recovery, online/offline behavior, and consistency checks](./F/F-08.md#8-practice) — Place parent and child tables in separate lab tablespaces. Back up them and perform an isolated table-space restore/rollforward in a clone. Check dependencies and data time point. No lab server is available here, so command path is not executed. Cleanup the clone only after preserving evidence.
- [F-09 Recovery failure drills, decision trees, legal next steps, evidence, and measured RTO](./F/F-09.md#8-practice) — Run tabletop drills for corrupt stripe, missing log, expired key, full restore volume and wrong database alias. For each, list evidence, legal next action, terminal point, business decision and elapsed time. Do not stage destructive failure in an unavailable/non-disposable system.
- [D-01 Authentication, operating-system identity, providers, and security plugins](./D/D-01.md#8-practice) — Configure two synthetic identities in a disposable directory/lab model.
