Shell DBA Runbooks and Collectors

Build a read-only collector with an allowlisted target, timeout, private output, and structured timestamps.

Level: Advanced · Effort: 2 hours
Prerequisites: J-01, E-01, and E-02.
Version scope: Db2 LUW 12.1 is the primary reference. Confirm syntax and monitor columns against the installed fix pack; 11.5 compatibility is stated only where checked.
Outcomes · How it works · Examples and commands · Diagram · Known issues and fixes · Lab · Review

Learning outcomes

  • Use secure temporary paths and restrictive file permissions.
  • Apply per-command timeouts and target allowlists.
  • Redact secrets and preserve structured command results.

How it works and when to use it

A collector gathers bounded evidence without changing database state. Record host, instance, database/member, command, time, return code, and output path. Timeouts protect against hangs but do not prove a utility stopped safely. Output can contain SQL, usernames, hosts, or sensitive data; permissions, retention, and redaction must be explicit. Retry only read-only/idempotent actions.

Decision rule: Default to dry-run/read-only, reject unknown aliases, create private output, and isolate each command timeout/status.

Worked examples and commands

Create a private collector directory

umask 077; outdir=$(mktemp -d "${TMPDIR:-/tmp}/db2collect.XXXXXX")

Expected / interpretation: The directory is private to the caller; store approved evidence only and apply retention controls.

Run a bounded identity query

timeout 30s db2 -x "VALUES CURRENT SERVER, CURRENT USER" > "$outdir/identity.txt" 2>&1; rc=$?; printf "%s	%d
" "$(date -u +%FT%TZ)" "$rc" >> "$outdir/status.tsv"

Expected / interpretation: A timeout returns nonzero; interpret command termination and database-side work separately.

Capture a bounded diagnostic window

timeout 30s db2diag -H 30m > "$outdir/db2diag.txt" 2>&1; rc=$?; printf "%s	%d
" "$(date -u +%FT%TZ)" "$rc" >> "$outdir/status.tsv"

Expected / interpretation: Redact tokens and retain originals securely; diagnostics may expose environment details.

Collector architecture: Bounded evidence capture with safe file handling

The collector preserves evidence and failure state without silently repeating a mutation.

Known issues, errors, fixes, and verification

Collector hangs indefinitely.

Likely cause: Network retry, CLI prompt, blocked connection, or utility takes longer than expected.

Fix: Use a time limit, noninteractive connection approach, distinguish timeout from failure, and preserve partial output.

Verify: Simulate an unreachable lab endpoint and confirm collection proceeds to the next bounded item.

Output files are readable by other users.

Likely cause: Default umask or directory permissions allow broad access.

Fix: Set restrictive umask before creation and verify ownership/mode.

Verify: Check permissions and confirm no secret values were captured.

A retry duplicates an administrative action.

Likely cause: The collector retried a write command with unknown completion state.

Fix: Keep collectors read-only; for mutations reconcile state before retry.

Verify: Failure injection routes unknown completion to manual review.

Hands-on lab: Create a safe diagnostic collector

Objective: Collect target identity and recent diagnostics into a private, timestamped directory.

  1. Allowlist a lab alias and load the correct instance environment.
  2. Set restrictive permissions and create a unique output directory.
  3. Run identity and db2diag commands with individual time limits.
  4. Record UTC, command label, return code, and redaction/retention metadata.

Answer key: Output proves target, time, command result, permissions, and bounded execution without credentials.

Cleanup: Remove the private lab output after recording the expected result.

Review question and answer

Question: Why disable automatic retry for an admin command that timed out?

Answer: A timeout leaves completion unknown; retry could execute the mutation twice. Reconcile state first.
