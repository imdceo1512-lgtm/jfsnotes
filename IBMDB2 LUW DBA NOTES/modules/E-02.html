db2diag.log, Notification Logs, and Diagnostic Signatures

Read Db2 diagnostic records by time, severity, process, member, and message tokens.

Level: Intermediate · Effort: 1.5 hours
Prerequisites: E-01 and B-04.
Version scope: Db2 LUW 12.1 is the primary reference. Confirm syntax and monitor columns against the installed fix pack; 11.5 compatibility is stated only where checked.
Outcomes · How it works · Examples and commands · Diagram · Known issues and fixes · Lab · Review

Learning outcomes

  • Locate the effective diagnostic path.
  • Filter diagnostic records to a time window or signature.
  • Correlate message tokens without treating one line as proof of cause.

How it works and when to use it

db2diag.log records Db2 diagnostic information; notification logging can surface selected events through the configured notification destination. Records contain timestamps and context such as process, application, member, function, severity, and tokens. Diagnostic verbosity and rotation affect retention. A message identifies an event or failure point; root cause may precede it in the same operation or live in host/network/storage evidence.

Decision rule: Locate the log, filter narrowly around a known UTC interval and token, then correlate the application/member and relevant OS evidence before assigning cause.

Worked examples and commands

Read the diagnostic directory

db2 get dbm cfg | grep -i DIAGPATH

Expected / interpretation: The effective DIAGPATH identifies where Db2 writes diagnostics; verify current instance and filesystem.

Show recent diagnostic history

db2diag -H 2h

Expected / interpretation: History duration uses supported units such as h and m. Run on the server and keep the output window tight.

Filter a known SQLCODE/message token

db2diag -g "DATA: SQL0551N" -H 2h

Expected / interpretation: Filter syntax and token availability depend on the record; start with broad time filter if exact token is absent.

Diagnostic correlation: Filter first, correlate, then explain

The diagnostic signature becomes useful when linked to the same operation and failure window.

Known issues, errors, fixes, and verification

No expected record appears in db2diag.log.

Likely cause: Wrong instance/path, log rotated, time window or timezone mismatch, or the operation did not emit a diagnostic record.

Fix: Confirm DIAGPATH and active instance; search rotated files and widen a bounded time interval using the source timestamp.

Verify: Find neighboring records with matching process/application ID and confirm file rotation coverage.

A warning is treated as the root cause.

Likely cause: The record reflects a downstream symptom or transient retry rather than the initiating fault.

Fix: Correlate earlier records, SQLCODE tokens, OS/storage/network evidence, and repeated behavior for the same application/member.

Verify: The proposed cause predicts a measurable outcome that changes after a controlled correction.

Diagnostic filesystem fills unexpectedly.

Likely cause: Rotation/size policy, increased diagnostic level, or noisy recurring errors exceed capacity.

Fix: Preserve required incident files, review DIAGSIZE and retention policy, correct recurring events, and size approved diagnostic storage.

Verify: Monitor directory growth and confirm new diagnostic records continue to be written.

Hands-on lab: Build a diagnostic time slice

Objective: Correlate one known error with its nearby Db2 records.

  1. Record the SQLCODE, host, member, application handle, and UTC time from a test failure.
  2. Read DIAGPATH and search a narrow window with db2diag.
  3. Inspect preceding and following records for the same process or application context.
  4. Compare with OS and client timestamps before writing a cause statement.

Answer key: The conclusion states what the record proves, what remains uncertain, and the next evidence needed to establish cause.

Cleanup: No log deletion or diagnostic-level change; retain only approved incident evidence.

Review question and answer

Question: Does the nearest preceding db2diag entry always identify the root cause?

Answer: No. It is a correlated clue. Verify context and causal sequence with other evidence.
