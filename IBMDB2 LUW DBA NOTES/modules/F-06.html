Incremental and Delta Restore Chains

Restore cumulative and noncumulative image chains in order and resolve automatic chain discovery failures safely.

Level: Advanced · Effort: 3 hours
Prerequisites: F-03 and F-04; isolated database and complete synthetic image chain.
Version scope: Db2 LUW 12.1 is the primary reference. Confirm syntax and monitor columns against the installed fix pack; 11.5 compatibility is stated only where checked.
Outcomes · How it works · Examples and commands · Diagram · Known issues and fixes · Lab · Review

Learning outcomes

  • Distinguish target image from base and intermediate images.
  • Explain automatic versus manual incremental restore.
  • Resolve a failed automatic restore without guessing the chain.

How it works and when to use it

An incremental restore identifies a target image, reads it for metadata, restores the latest full baseline, then applies required images in order. The target image is accessed again to complete processing. Automatic mode uses database history to assemble the chain. Manual mode requires one RESTORE for each image. A delta chain needs every intervening required image; cumulative incremental can reduce dependency count. Cross-platform and release compatibility restrictions apply to incremental/delta images.

Decision rule: Use automatic mode when history and all artifacts are intact. If Db2 cannot build a complete chain, follow the documented abort process, inventory all images, and rehearse manual sequencing in isolation.

Worked examples and commands

Automatic incremental restore to a target image

db2 restore db SAMPLE incremental automatic from /db2backup taken at 20261027010000

Expected / interpretation: TAKEN AT identifies the final image. Db2 uses database history to locate the chain; keep history and image files available throughout.

Manual incremental restore order

db2 restore db SAMPLE incremental from /db2backup taken at 20261027010000
db2 restore db SAMPLE incremental from /db2backup taken at 20261026010000
# Apply every intervening image in creation order, then repeat the target image:
db2 restore db SAMPLE incremental from /db2backup taken at 20261027010000

Expected / interpretation: Manual mode reads the target image first to establish history, restores the base full image, then applies every required image in creation order; the target image is read again at the end. Confirm the chain with Db2 history and the IBM db2ckrst utility before recovery.

Monitor incremental restore progress

db2 list utilities show detail

Expected / interpretation: When a restore utility is active, inspect its type, database, state, and progress before deciding whether to wait or investigate.

Incremental restore sequence: Target identification, baseline, and chronological application

The target is selected first, but the data chain is rebuilt from the baseline forward.

Known issues, errors, fixes, and verification

Automatic restore cannot determine a complete image chain.

Likely cause: History or required image files are missing, pruned, inaccessible, or incompatible.

Fix: Preserve utility state and issue documented INCREMENTAL ABORT if an automatic operation is in progress; reconstruct the chain from retained evidence.

Verify: A lab restore completes from the exact base and target set with matching database identity.

Restore selects the wrong target point.

Likely cause: TAKEN AT is not the intended final image timestamp or backup start/completion time is confused.

Fix: Reconcile history and image metadata before starting. If a wrong chain began, use the documented abort procedure and restart in a clean target.

Verify: Check recovery timestamp and known data markers against the requested point.

Incremental restore fails across a platform or word-size change.

Likely cause: Incremental/delta compatibility restrictions are stricter than those of a supported full-image migration.

Fix: Use an IBM-supported migration route and compatible full baseline; do not force an incremental chain across incompatible platforms.

Verify: Confirm source/target compatibility in release documentation and complete a migration restore test.

Hands-on lab: Restore a mixed full/incremental/delta sequence

Objective: Reconstruct a target point without omitting an image.

  1. Create a schedule with one full, two delta images, one cumulative incremental, and a final delta.
  2. List required images for automatic and manual restore.
  3. Remove one intermediate image from the lab inventory and document why the chain fails.
  4. Restore the missing artifact, perform manual sequencing, and verify a target row/version marker.

Answer key: Automatic restore needs usable history and every required image. Manual restore needs the target identity, baseline full, and all subsequent images in order. Rollforward may still be required after image application.

Cleanup: Drop only the disposable target; retain synthetic images.

Review question and answer

Question: What distinguishes automatic from manual incremental restore?

Answer: Automatic mode uses history to discover and apply the chain from one target request; manual mode issues RESTORE for each required image.
