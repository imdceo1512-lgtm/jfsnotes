Db2 Catalogs and Administrative Interfaces

Choose metadata and monitoring interfaces for inventory, state, and activity questions.

Level: Intermediate · Effort: 2 hours
Prerequisites: B-01 and C-02.
Version scope: Db2 LUW 12.1 is the primary reference. Confirm syntax and monitor columns against the installed fix pack; 11.5 compatibility is stated only where checked.
Outcomes · How it works · Examples and commands · Diagram · Known issues and fixes · Lab · Review

Learning outcomes

  • Distinguish catalog metadata from live monitoring metrics.
  • Query object metadata with schema-qualified filters.
  • Check authority, freshness, and release-specific columns.

How it works and when to use it

SYSCAT views describe objects and their definitions. Administrative views and MON_GET routines expose operational metrics, often scoped by member or activity and sampled at call time. These sources answer different questions. A catalog row does not prove an object is healthy or in use; a monitoring value does not replace a durable inventory. Confirm database identity and column availability on the target release before publishing a production query.

Decision rule: Use SYSCAT for what is defined, administrative and monitor interfaces for what is happening, and diagnostic records for why an event occurred. Join them only on documented keys and preserve timestamps and scope.

Worked examples and commands

Inventory table spaces

db2 "SELECT TBSPACE, TBSPACETYPE, PAGESIZE, AUTORESIZE, DATATYPE FROM SYSCAT.TABLESPACES ORDER BY TBSPACE"

Expected / interpretation: Shows catalog definition fields; confirm exact view columns on the server release.

Find tables by schema

db2 "SELECT TABSCHEMA, TABNAME, TYPE, CREATE_TIME FROM SYSCAT.TABLES WHERE TABSCHEMA = 'APP' ORDER BY CREATE_TIME DESC"

Expected / interpretation: Catalog inventory is database-specific and requires a connected database.

Sample live database metrics

db2 "SELECT MEMBER, TOTAL_CPU_TIME, ROWS_READ, ROWS_RETURNED FROM TABLE(MON_GET_DATABASE(-2)) AS M"

Expected / interpretation: A monitor function returns current cumulative counters; compare two time-separated samples to calculate a rate.

Interface selection flow: Choose the interface based on the question

Capture version, database identity, and sample time so results remain interpretable.

Known issues, errors, fixes, and verification

SQL0206N reports an undefined column in a catalog query.

Likely cause: The query assumes a column from another release, view, or fix pack.

Fix: Inspect catalog view definitions for the actual server level and remove or version-gate unsupported columns.

Verify: Prepare the query on each supported release and record the Db2 server version with results.

Catalog query returns no rows although the object is visible to an application.

Likely cause: Connected to a different database, filtering on wrong schema/case, or authorization hides metadata.

Fix: Check current server/database/user, resolve schema and object IDs, and use approved catalog visibility authority.

Verify: Compare the fully qualified object in application connection details and query it from the same alias.

A single monitor snapshot is interpreted as a rate.

Likely cause: The returned counters are cumulative or member-scoped.

Fix: Capture two samples at known times, retain member identity, and compute deltas over elapsed seconds.

Verify: Compare the derived rate with a second independent interval and workload context.

Hands-on lab: Answer three inventory questions

Objective: Use a catalog query and a monitor query for distinct questions.

  1. Record Db2 release, database alias, and authorization ID.
  2. Use SYSCAT.TABLES to find APP tables and object types.
  3. Use a documented MON_GET routine twice, 60 seconds apart.
  4. Explain which result is definition metadata and which is sampled activity.

Answer key: Catalog query identifies defined objects; monitor query reports live counters, and delta plus elapsed time is required for a rate.

Cleanup: No changes; save query text and sample timestamps.

Review question and answer

Question: Why can a SYSCAT query not replace MON_GET_DATABASE?

Answer: The catalog describes definitions; the monitor function reports runtime activity and counters.
