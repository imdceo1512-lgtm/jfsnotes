Backup Types and Command Selection

Choose offline/online, full, incremental, delta, tablespace, or snapshot approaches using their distinct recovery costs.

Level: Intermediate · Effort: 2.5 hours
Prerequisites: F-01 and F-02.
Version scope: Db2 LUW 12.1 is the primary reference. Confirm syntax and monitor columns against the installed fix pack; 11.5 compatibility is stated only where checked.
Outcomes · How it works · Examples and commands · Diagram · Known issues and fixes · Lab · Review

Learning outcomes

  • Explain the baseline dependency for each backup type.
  • Choose a type for a stated workload and recovery objective.
  • Recognize incompatible combinations and online-backup prerequisites.

How it works and when to use it

A full image supplies a complete baseline. A cumulative incremental contains changes since the latest full image; a noncumulative delta contains changes since the latest successful backup of any type. Their restore chains differ. Online backup permits concurrent database access but requires archive logging. A tablespace image narrows physical scope but retains consistency dependencies. Snapshot backup uses a different mechanism and has option restrictions; it is not a synonym for an ordinary online database image.

Decision rule: Choose offline when downtime is acceptable. Choose online when availability is required and archive logging is configured. Use incremental/delta only when the saved chain and restore process are operationally supported.

Worked examples and commands

Offline full database backup

db2 backup db SAMPLE to /db2backup

Expected / interpretation: ONLINE is omitted, so this is the default offline pattern. Schedule it with the database connection impact understood.

Online full, cumulative incremental, and delta

db2 backup db SAMPLE online to /db2backup include logs
db2 backup db SAMPLE online incremental to /db2backup include logs
db2 backup db SAMPLE online incremental delta to /db2backup include logs

Expected / interpretation: The second image is cumulative since the latest full; the third is noncumulative since the latest successful backup of any type. Online backup requires archive logging.

Tablespace-level backup

db2 backup db SAMPLE tablespace (USERSPACE1) online to /db2backup

Expected / interpretation: The image covers the named tablespace, not the whole database. Record its timestamp, table-space list, log requirements, and cross-space dependencies.

Backup-chain comparison: Cumulative incremental versus noncumulative delta

The delta chain depends on each prior backup, while the cumulative image independently covers changes since the full baseline.

Known issues, errors, fixes, and verification

An online backup is rejected or cannot start.

Likely cause: The database is not configured for rollforward recovery or its archive method is unusable.

Fix: Check effective LOGARCHMETH1/2 and archive access; execute the documented logging transition before retrying.

Verify: Confirm configuration and complete a controlled online backup with image metadata recorded.

A delta image is treated as cumulative.

Likely cause: The operator assumes the newest image contains every change since the full backup.

Fix: Use history and schedule to identify every intervening image. If the chain is uncertain, use a known-good full or test automatic restore.

Verify: Restore the selected target in isolation and confirm the recovered point and data marker.

Snapshot options conflict with a tablespace or incremental request.

Likely cause: Snapshot backup does not support all ordinary BACKUP options.

Fix: Use an ordinary BACKUP workflow for that scope or redesign the snapshot with only release-supported options.

Verify: Review the release-specific command syntax and restore-test the resulting artifact.

Hands-on lab: Build and restore a weekly image chain

Objective: Show how backup choice changes restore dependencies.

  1. Use a synthetic schedule: Sunday full, Monday/Tuesday delta, Wednesday incremental, Thursday delta.
  2. List the required images for a Friday target in automatic and manual mode.
  3. Compare the chain with a full-only plan for storage and RTO.
  4. Choose a tablespace image for a one-space incident and identify dependencies.

Answer key: The cumulative Wednesday image covers changes since Sunday’s full; each delta depends on the most recent successful backup. Automatic restore uses history; manual restore applies required images in the documented order.

Cleanup: Planning exercise only; no live database work.

Review question and answer

Question: Why can a smaller delta image increase recovery risk or time?

Answer: It depends on every required prior image in its chain; a missing image can prevent restore and more images may need application.
